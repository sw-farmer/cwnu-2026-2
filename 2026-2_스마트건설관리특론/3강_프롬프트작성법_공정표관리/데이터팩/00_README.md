> 스마트건설관리특론 3주차 실습용. **교육용 가상 현장**이며, 작업 기간·기상 비작업일·단축비용·간접비는 가정값입니다(각 행의 `근거` 열 참조).

### 주요 열
- `activities.csv`: 작업코드(1 / 1.1 / 1.1.1) · 상위코드 · 레벨 · 작업명 · 공종 · 층 · 기간(작업일) · 캘린더(STD/WX) · 근거
- `relations.csv`: 선행 · 후행 · 관계(FS/SS) · 시차(달력일) · 비고
- `baseline_schedule.csv`: 구분(요약/세부) · 시작일 · 종료일 · 최늦시작 · 최늦종료 · 여유(작업일) · 주공정(★)

## 3. 계산 규약 (AI·검증기 공통)
1. **기간** = 작업일 수. 해당 작업 캘린더의 작업 가능일만 센다. 시작일·종료일 모두 포함(기간 1 → 시작일 = 종료일).
2. **캘린더**: `STD`(Standard, 표준) = 토·일·법정공휴일 휴무, `WX`(Weather, 기상) = STD + 기상 비작업일 휴무(토공·타설·외부 작업). `calendar.csv`의 1/0을 그대로 쓴다.
3. **관계**: `FS` 후행 시작 ≥ 선행 종료일 + 1 + 시차 / `SS` 후행 시작 ≥ 선행 시작일 + 시차. 그날이 후행 캘린더의 휴무일이면 다음 작업 가능일.
4. **시차** = 달력일(콘크리트 양생처럼 휴일에도 흐르는 시간).
5. 관계는 세부작업끼리만 있다. 요약 행 일정 = 자식의 최소 시작 ~ 최대 종료.
6. **여유** = 그 작업을 늦춰도 준공이 안 늦어지는 작업일 수(실제로 그만큼 늦춰 보면 준공이 그대로임).
7. **주공정(★)** = 준공일을 결정하는 연속 경로(각 작업의 시작을 실제로 결정한 선행을 준공에서 거슬러 추적, 최장 경로 방식). 주말·공휴일·기상 휴무가 섞이면 ★ 작업에도 여유 1~4일이 생길 수 있다(달력이 흡수). 그래서 '여유 0'만으로 찾으면 길이 끊긴다. **주공정 여부는 `주공정` 열(★)**, 단축 효과는 반드시 검증기 `--crash`로 확인(SS 관계·달력 때문에 ★ 작업을 줄여도 준공이 안 당겨질 수 있음).
8. 마일스톤은 별도 작업이 아니라 `project.json`에 정한 작업의 종료일(착공만 시작일).

## 4. 검증기 사용법 (데이터팩 폴더에서 실행)
```
python check_schedule.py                                   # 기준 공정표 요약(준공일·마일스톤·주공정)
python check_schedule.py --compare ..\outputs\일정_표시용.csv  # 공정표에 쓴 일정이 기준과 같은지 대조
python check_schedule.py --progress progress_2026-09-30.csv  # 6개월차 실적 반영 → 준공 예측·지연
python check_schedule.py --progress progress_2026-09-30.csv --crash ..\outputs\단축안.csv
                                                           # 단축안(작업코드,단축일) → 새 준공일·추가비용·간접비 절감
python check_schedule.py ... --out ..\outputs\결과.csv      # 계산 결과 저장
```
- `--compare` 파일 필수 열: `작업코드, 시작일, 종료일` (선택: `여유`), 날짜는 `YYYY-MM-DD`.
- 마지막 줄이 `[통과]`면 통과, `[실패]`면 표시된 항목을 고쳐 다시 실행.
